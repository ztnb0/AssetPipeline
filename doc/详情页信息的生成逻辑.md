# 详情页信息的生成逻辑

## 1. 当前完成情况

目前对外可用的是**图片和视频**素材的详情信息生成。信息不是在打开详情页时临时生成，而是在上传或从外部平台导入后，由 FastAPI 后台任务异步分析并写入 MySQL；详情弹窗只读取、展示和修改已有数据。

```text
本地上传 / 外部平台导入
    ↓
原文件保存到 MinIO 的“未分类”目录
    ↓
MySQL 创建 processing 状态的 Asset
    ↓
FastAPI BackgroundTasks 执行 process_asset(asset_id)
    ├─ 图片：读取尺寸 → 生成缩略图 → Qwen 单图分析
    └─ 视频：FFprobe → 5 个时间点抽帧 → Qwen 多帧分析
    ↓
描述、场景、分类、标签、技术参数写入 MySQL
    ↓
原文件移动到主分类目录，并写入 Qdrant 向量索引
    ↓
状态变为 ready，前端轮询后展示详情
```

当前功能边界：

- 图片、视频上传和分析已开放。
- Pexels、Pixabay、Unsplash、Openverse、Mixkit 外部素材导入已接入；导入后走同一套分析流程。
- 音频的 FFprobe、Whisper ASR 和文本分析代码已经实现，但上传、列表筛选和搜索接口当前返回 HTTP 410，因此暂不属于可用功能。
- 图片/视频比例裁剪与导出代码和界面已经实现，但前后端开关均为 `false`，接口当前返回 HTTP 410，尚未开放。
- FRED 财经图表生成接口当前也处于停用状态，与详情信息生成主流程无关。

## 2. 创建基础记录

本地上传入口是 [`POST /api/assets/upload`](../backend/app/main.py)，外部导入入口是 [`POST /api/external-assets/import`](../backend/app/main.py)。两者最终都调用 `_create_asset()`：

1. 根据 MIME 类型或扩展名判断 `image`、`video` 或 `audio`。
2. 检查文件是否为空及是否超过配置的上传上限。
3. 计算文件内容的 SHA-256，写入 `content_hash`。
4. 将原文件保存到 `media/{media_type}/未分类/{asset_id}.{suffix}`。
5. 在 MySQL 创建 `Asset`，状态为 `processing`，初始分类为“未分类”。
6. 通过 `BackgroundTasks` 启动 `process_asset(asset.id)`。
7. 立即返回 HTTP 202。

因此，HTTP 202 只表示素材已经进入处理流程，不表示详情信息已经生成完成。

基础记录包含原始文件名、MIME 类型、文件大小、素材类型、MinIO 对象地址、内容哈希和创建时间。外部导入还会保存平台、外部素材 ID、原始页面、作者、许可和来源元数据。数据模型见 [`backend/app/models.py`](../backend/app/models.py)。

## 3. 图片详情信息

图片处理逻辑位于 [`backend/app/processor.py`](../backend/app/processor.py) 的 `_process_image()`：

1. 使用 Pillow 打开图片，并根据 EXIF 自动纠正方向。
2. 读取原图宽高，写入 `width`、`height`。
3. 将图片缩放到最大 `640 × 640`，生成 WebP 缩略图 `thumbnails/{asset_id}.webp`。
4. 将原图以 Base64 形式发送给 Qwen 兼容的多模态接口。
5. 保存模型返回的 `description`、`scene`、`tags`、`categories`。
6. 将第一项分类同步为主分类 `category`，并记录 `media_metadata.analysis_version = visual-v2`。

图片提示词定义在 [`backend/app/analyzer.py`](../backend/app/analyzer.py)，要求返回严格 JSON：

```json
{
  "description": "画面中两名商务人士坐在会议桌旁交谈，桌上放有电脑和文件。",
  "tags": ["商务人士", "会议", "交谈", "办公室"],
  "scene": "办公室内商务人员讨论工作方案",
  "categories": ["商业"]
}
```

提示词要求只描述可观察事实，不能无依据推断人物身份、品牌、认证资格、金融结论或人物意图。

## 4. 视频详情信息

视频处理逻辑位于 [`backend/app/processor.py`](../backend/app/processor.py) 的 `_process_video()`，分为技术解析和内容分析两部分。

### 4.1 技术解析

FFprobe 解析以下信息：

- 时长、封装格式和总码率；
- 视频流和音频流；
- 编码格式、宽高、帧率、采样率和声道数。

时长和宽高写入 Asset 的独立字段，其余信息保存在 `media_metadata`。

### 4.2 抽帧与内容分析

后端在视频时长的 5%、25%、50%、75%、95% 位置各提取一帧；极短视频只取起始帧。抽帧宽度最大为 1280 像素，第一张成功抽出的帧同时保存为 `thumbnails/{asset_id}.jpg`。

最多五帧按时间顺序一次发送给 Qwen，并附带真实时间点、文件名和视频时长。模型返回整段描述、主要场景、标签、分类和逐帧描述：

```json
{
  "frame_analysis": [
    {"timestamp": 5.2, "description": "主持人站在演播室屏幕前"}
  ],
  "description": "视频主要展示主持人在财经演播室讲解市场走势。",
  "tags": ["主持人", "财经演播室", "市场走势"],
  "scene": "财经演播室主持人解读市场走势",
  "categories": ["财经", "金融市场"]
}
```

`frame_analysis` 保存在 `media_metadata`，用于构建检索文本；当前详情弹窗尚未展示逐帧描述。

## 5. AI 结果校验

模型调用和结果清洗位于 [`backend/app/analyzer.py`](../backend/app/analyzer.py)：

- 去除 Markdown 代码块，并解析 JSON；若夹杂额外文字，则尝试提取第一个 JSON 对象。
- 标签去空、去重，视觉分析最多保存 20 个。
- 分类必须来自预定义题材表，最多保留 3 个；没有合法分类时回退为“其他”。
- 视频逐帧结果重新绑定后端实际抽帧时间，避免采用模型生成的错误时间点。
- 调用参数为 `temperature = 0.1`、`enable_thinking = false`，用于降低输出波动。

这些措施能提高结构稳定性，但描述、场景、标签和分类本质上仍是 AI 生成结果，可在详情页人工修订。

## 6. 完成、失败与重新分析

统一处理入口是 [`process_asset()`](../backend/app/processor.py)：

- 分析成功后，状态改为 `ready`，清空 `error_message`，第一项分类成为主分类。
- 原文件从“未分类”移动到 `media/{image|video}/{主分类}/{asset_id}.{suffix}`。
- 数据提交后，系统尝试把名称、描述、场景、分类、标签、视频逐帧描述等写入 Qdrant 向量索引。
- 向量写入失败只记录日志，不会把已经完成分析的素材改为失败；关键词检索仍可使用。
- 分析异常时，状态改为 `failed`，异常摘要写入 `error_message`。

前端上传队列可调用 [`POST /api/assets/{id}/reanalyze`](../backend/app/main.py) 重新分析失败或已完成的素材。该接口会把状态重置为 `processing`、清除错误、删除旧向量，再次启动同一处理流程。

后台使用进程内信号量限制最多同时运行两个 FFmpeg、Qwen 或 Whisper 分析任务。当前没有持久化任务队列，API 进程重启时，正在运行的后台任务不会自动恢复。

## 7. 详情页取数与展示

输出结构定义在 [`backend/app/schemas.py`](../backend/app/schemas.py)。`serialize()` 会为本地素材补充：

```text
content_url   = /api/assets/{id}/content
thumbnail_url = /api/assets/{id}/thumbnail
```

前端初次加载通过 `GET /api/assets` 获取列表。只要列表中存在 `processing` 素材，就每两秒重新拉取一次列表。上传队列还会针对处理中项目调用 `GET /api/assets/{id}` 更新状态。

点击素材卡片时，当前实现不会额外请求详情接口，而是把列表中已有的完整 Asset 对象传给 `AssetDetail` 弹窗。详情弹窗位于 [`frontend/app/page.tsx`](../frontend/app/page.tsx)，展示：

- 内容信息：名称、多选分类、具体场景、描述、标签和处理状态；
- 媒体预览：图片原图或视频播放器；
- 技术信息：类型、格式、大小、时长、分辨率、编码、码率、帧率、来源、作者、许可和上传时间。

视频的逐帧分析目前不直接展示。音频相关的播放器、ASR 转写和采样信息界面虽已存在，但由于音频接口停用，正常使用流程不会产生新的音频详情数据。

## 8. 人工修改与索引同步

详情页允许修改名称、分类、场景、描述和标签，保存时调用 `PATCH /api/assets/{id}`：

- 标签会去空、去重，最多保留 30 个。
- 分类至少保留一项，最多接收 8 项。
- 第一项分类作为主分类；主分类变化时，后端同步移动 MinIO 中的原文件目录。
- 保存成功后重新生成该素材的向量索引，使后续搜索使用最新详情信息。

删除素材时，系统同时删除原文件、缩略图、该素材的导出缓存和 Qdrant 向量；批量删除走同一清理规则。

## 9. 已实现但尚未开放的比例导出

[`backend/app/media_export.py`](../backend/app/media_export.py) 已实现图片和视频的 `9:16`、`16:9`、`4:3`、`3:4` 导出，包括完整显示、智能裁剪、手动焦点、缩放、视频分段焦点跟踪和 MinIO 导出缓存。前端也已实现裁剪预览界面。

但当前 `backend/app/main.py` 的 `FORMAT_EXPORT_ENABLED` 和 `frontend/app/page.tsx` 的同名开关都为 `false`。因此按钮不会显示，`POST /api/assets/{id}/export` 返回 HTTP 410。该能力目前应视为“代码已完成、产品未开放”，不能作为详情页现有可用功能对外说明。
